iDotDot

HTML CSS JS Static 2026

A static portfolio and playground site built from scratch with no frameworks and no build step — just HTML, CSS, and vanilla JavaScript with a retro DOS/CRT aesthetic.

Background

I wanted a portfolia site that was me — not based on a theme, not a template, not a SaaS portfolio builder. I must preface: I do not come from web development, so I used this as a learning experience - and the structure is pretty messy. The DOS terminal aesthetic stems from my system and app-level expertise. Sprinkled around are also little easter eggs, a by-product of my game design passion.

The constraint of zero dependencies and no build tooling was intentional. Frameworks are fine — I use them plenty elsewhere — but for a personal site I wanted to showcase my capability.

Design

The visual language is phthalo green on black, monospaced type throughout, and CRT scanlines applied in pure CSS. Every color is a CSS variable on :root so the entire palette can be swapped at runtime — which is exactly what the theme switcher does. The priority was to establish a "tone" and stick with it. Only breaking it for real accessbility purposes. Some functionality exists purely just to force me to learn something new. For example: I never worked with web canvas drawing before. Heading elements run through a glitch pass on an interval, randomly corrupting one to three characters for ~300ms to simulate phosphor decay.

Type theme amber, theme cyan, theme white, or theme red into the terminal footer to switch palettes. The choice persists in localStorage across pages.

Terminal Footer

The footer was made for... well, me. I have no rhyme or reason as to why it exists or why it does what it does. But I really like it. It reads like a shell prompt and reacts to everything happening in the page above it. Hovering a link or project card auto-completes a cd command reflecting the navigation target. Selecting text on the page shows a copy "..." preview. Clicking the footer activates keyboard input — type characters, hit Enter to run a command, Escape to clear.

A small commands.js module handles dispatch: built-in commands like cd home, theme 'name', and a few easter eggs route to navigation, theme changes, flash messages, or dynamically imported game modules. Unknown input flashes an error. The whole system is about 130 lines and zero dependencies.

Architecture

Content lives in data.js — two arrays, PROJECTS and POSTS. Adding a project is two steps: create the HTML file, add one object to the array. main.js renders the project grid and post list from that data at runtime; there is no static generation step.

  • main.js — renders the project grid and post list, runs the typewriter effect
  • footer.js — terminal footer interactions and keyboard handling
  • commands.js — command dispatch and routing logic
  • glitch.js — periodic character corruption on headings
  • theme.js — reads/writes localStorage, applies theme class on load
  • data.js — the only file you need to touch to add content

Project detail pages each import a shared project-shell.js that re-initializes the footer with the correct prompt path, keeping the terminal context consistent as you navigate between pages. I want to look into removing even more duplicate logic between project pages, but that's for a later time.

Hero Typewriter

The hero subtitle cycles through a list of descriptors using a simple async loop — type forward at 80ms per character, hold for 3 seconds, erase at 45ms per character, repeat. No library. The list includes the expected ones (software developer, problem solver) and a few that are less expected.

Final Thoughts

I actually enjoyed restricting myself to no dependencies or external libraries. It means no install, no compile step. Open index.html in a browser. ES6 modules require a local HTTP server for proper import resolution in most browsers: 

npx serve .

That's it. No node_modules, no config files, no bundler. There were a lot of areas of learning that pissed me off about web development. But overall it was a great experience, and I'll keep adding to this site.
