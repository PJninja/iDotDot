iDotDot

HTML CSS JS Static 2026

A static portfolio and playground built from scratch — no frameworks, no build step. Just HTML, CSS, and vanilla JavaScript with a retro DOS/CRT aesthetic.

Background

I wanted a portfolio site that was me — not a theme, not a template. The DOS terminal aesthetic comes from my system and app-level background, and there are a few easter eggs in there from my game design side.

Zero dependencies and no build tooling was intentional. Frameworks are fine, but for a personal site I wanted to show what I could do without them.

Design

Phthalo green on black, monospaced type throughout, CRT scanlines in pure CSS. Every color is a CSS variable on :root so the entire palette swaps at runtime — which is exactly what the theme switcher does.

Some features exist just to make me learn something new. Headings run through a glitch pass on an interval, randomly corrupting characters for ~300ms to simulate phosphor decay.

Type theme amber, theme cyan, theme white, or theme red into the terminal footer to switch palettes. Persists in localStorage.

Terminal Footer

The footer reads like a shell prompt and reacts to what's happening on the page. Hover a link → cd auto-completes. Select text → copy "..." preview. Click the footer to type — Enter to run, Escape to clear.

Commands dispatch through a small commands.js module: cd home, theme 'name', and a few easter eggs. Unknown input flashes an error. About 130 lines, zero dependencies.

Why does this feature exist? Because I want it to. That is all.

Architecture

Content lives in data.js — two arrays, PROJECTS and POSTS. Adding a project is two steps: create the HTML file, add one object to the array.

  • main.js — renders the project grid and post list, runs the typewriter effect
  • footer.js — terminal interactions and keyboard handling
  • commands.js — command dispatch and routing
  • glitch.js — periodic character corruption on headings
  • theme.js — reads/writes localStorage, applies theme on load
  • data.js — the only file you need to touch to add content

Tidbits

  • Scanlines are pure CSS — a repeating linear gradient on a ::after pseudo-element covering the viewport. No canvas, no JS, no image.
  • Glitch avoids innerHTML — it surgically replaces a TEXT_NODE in-place with three nodes (before, glitch span, after), then swaps them back after 300ms. Safer and faster than string manipulation.
  • Footer tracks selections — it listens to the selectionchange event on document rather than polling. Zero overhead when nothing is selected.
  • These folders are runtime DOM restructuring — there are no section wrappers in the HTML source. project-shell.js walks the h3 elements at load time, groups each one with its following siblings, and wraps them into collapsible sections before the first paint.
  • Theme switching is a single class swap — all palette values are CSS variables on :root. Switching themes just toggles a class on <body> and writes the choice to localStorage. No style recalculation, no re-render.
  • Hero Typewriter — The hero subtitle cycles through descriptors — type at 80ms per character, hold 3 seconds, erase at 45ms, repeat. No library. The list includes the expected ones (software developer, problem solver) and a few that are less expected.

Final Thoughts

This project took me out of my comfort zone. It pulled me into the world of pure css, html, and js without relying on libraries. With already a disdain for web development, and some practices that genuinely pissed me off, it took me a long time to get something functional and working completed. But here we are. And overall, I enjoyed the process and will keep adding to this.
