Unspeakable Horrors Race Betting

Svelte 5 Fastify WebSocket Game Node.js 2026

A browser-based betting game where players wager "candies" on procedurally generated eldritch monsters racing each other.

GITHUB PLAY

Background

It Started as a joke — horse racing, but every horse is a cosmic abomination from Lovecraft's nightmares? It grew into a full-stack experiment: procedural content generation, real-time multiplayer state, and deceptive UI design.

The goal was a game that feels alive and mysterious. Players should rarely see raw numbers, but gradually learn to read the monsters the same way a gambler learns to read a horse.

How It Works

  • Races trigger every 30–300 seconds with 4–6 uniquely generated creatures
  • Players read monster bios, decode hidden stat signals, and bet on a winner
  • Single shared server — everyone sees the same Horrors, same outcomes, same pool
  • State machine — server cycles waiting → racing → finished over WebSocket; client navigation is forced by state
  • Anti-cheat — payout endpoint ignores client claims and recomputes bet × odds server-side
  • Two-simulation design — server picks the winner; client runs a visual sim so races look contested but always finish in the right order

No stat numbers are ever shown. Power tier, dominant stat, crowd sentiment, and odds are communicated through prose, glow effects, and alchemical symbols. Build intuition by cross-referencing bios with outcomes.

Hidden Stat System

Each Horror has four stats — Speed, Endurance, Madness, and Strength — encoded invisibly into its bio text.

  • Catalog entries (Origin, Traits, Race Style, etc.) are each tagged with a letter: A C G T
  • Letters map to stat categories; letter count sets the stat total
  • Luck is derived from letter variety — more unique letters means more unpredictable
  • Each stat has a RichText style that visually hints at strength — e.g. high Speed gets more <glow> tags in its bio

There's also a hidden "value" per Horror that drives ~70% of the odds, with stats only ~30%. A statistically dominant monster can still be a bad bet if they're heavily favored.

Legendaries spawn at 5% chance per race, capped at 1.5× base stats — favored, but not guaranteed.

Simulation Tool

Balance is hard to verify manually, so the game ships with a CLI simulator that runs thousands of races against the same production logic — no server needed. Fully deterministic with --seed for before/after tuning comparisons.

This tool caught that Madness was too dominant, leading to a rework that made high-Madness monsters more volatile rather than more likely to win.

node server/scripts/simulate.js --races 1000 --quiet
node server/scripts/simulate.js --races 500 --seed my-seed --quiet
node server/scripts/simulate.js --races 1000 --format csv --output results.csv

Stack

  • Frontend — Svelte 5, svelte-spa-router, Vite
  • Backend — Fastify, @fastify/websocket, @fastify/rate-limit
  • No database — in-memory session store, 24-hour TTL, hourly purge
  • Bet history — localStorage, capped at 50 races
  • Logging — Pino, structured + module-labeled, level via LOG_LEVEL
  • Tests — >150 total across both packages, Vitest 2.x
