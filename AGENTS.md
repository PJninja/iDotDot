# AGENTS.md — PJ.iDotDot

Personal portfolio site where the entire page is a falling-sands simulation.
TypeScript + Vite + **WebGPU compute**, **zero runtime dependencies** (devDeps: `typescript`, `vite` only).
WebGPU is required for the simulation; there is no CPU fallback. A browser without it (or a window too small for the chips) gets the plain page, an ordinary document rendered from the same project data.
The canvas fills the viewport below a fixed 48px header; HTML overlays carry the UI.

Behavior still has to be added to the compute shader. |

There is no test framework, only the small suites below (`npm run test:ui`, `npm run test:gpu`, `npm run test:pulse`). Validate with `npx tsc --noEmit` + `npm run build` + those, and verify behavior in a WebGPU browser (the work happens on the GPU, so it cannot run in Node). Check GPU validation errors: the device logs `uncapturederror` to the console, and a failed shader/pipeline makes the whole command buffer silently do nothing, so an error scope (`device.pushErrorScope('validation')`) is the reliable check.

### Testing in headless Chromium (`tools/browser/`)
Plain Node scripts (Node 22+) that start the dev server if it is not running and drive a headless Chromium with working software WebGPU. Playwright is not a repo dependency: `launch.mjs` finds it in `node_modules`, the global install, or `/opt/node-tools/node_modules/playwright`, and the browser at `$CHROMIUM_PATH` or `/opt/pw-browsers/chromium`. Write new scripts on `withPage(url, (page, log) => ...)` (a fresh browser) or `withSession((page, log) => ...)` (the warm one) from `launch.mjs`, which collect console errors, page errors and failed requests.

Pick the cheapest tool that answers the question:
- **The tests (`npm run test:ui`, `npm run test:gpu`) cover only critical paths: what changes often, differs by device, or breaks easily.** Edge cases, copy, colors and small states are left to review; do not add a check for those. Before adding one, ask whether a regression there would go unnoticed, and prove the new check can fail by breaking the code once.
- **`npm run test:ui`** (no GPU, seconds) runs the real board, window, project filter and route code in `tools/browser/harness/` against a fake world that records `stampCells` and draws the tiles into a 2D canvas. It checks: the board layout at desktop, large, browser-zoom (fractional tile size) and tablet (one column of big chips) and Pixel-class phone (2.625x, small chips) screens, at every tile size in the perf HUD dropdown (1, 2, 4, 8, 16 px), and a window too short for the board (only combinations that can occur; a 4 px tile at 1x, 1.25x, 1.5x, 2x or 3x is exactly 4 px, so those add nothing over 1x). For each: the expected number of chips (4 wide, 2 narrow, 2 compact) or the plain-page fallback, a chip's width (about 400 CSS px wide and narrow, 200 compact), every chip shows its tags in full, every chip's collider is exactly its cell box and none overlap, a tile ring fits exactly around every chip, and the chips and gallery stay inside the window. Also: the project window's open, Escape and focus return, detail hash, Back and focus trap; a hash deep link; browsing (a tag narrows the chips and lights their rings and Clear restores them, a tag in the URL, search and its no-match message, the pager); the plain page and the no-WebGPU notice. A browserless group, `pixel geometry`, checks `computeGridGeometry` and the header snap as arithmetic at every pixel ratio from 0.8x to 3x. Add a check in `test-ui.mjs` (a `group(name, url, body, options)` with `t(name, pass)`); `options` include `width`, `height` and `deviceScaleFactor`, and `window.__h` exposes the board, filter, window, colliders and stamped tiles (`?n=12` pads the project list so the pager has more pages). The harness is type-checked with the app (`tsconfig.json`). Groups run four browsers at a time (about 11 s in all); pass a name filter to run one group.
- **`npm run test:gpu`** (about 12 s) checks what only the real GPU shows: the app boots to a world with tiles, every chip's ring is in the GPU grid after the default world loads (the order `rebuildWorld` depends on), painting adds tiles, there are no errors or lost device, and at browser zoom 110% and a 2.625x phone the real canvas covers exactly its backing pixels, starts on a device pixel and every chip sits on whole tiles (within 0.05 device px, the browser's 1/64 px layout snap).
- **`npm run test:pulse`** (about 45 s) is the one simulation-behavior check: a pulse crosses a 31-cell steel wire and the wire ends up all steel with the sim idle. It guards the spent-steel stage (shortened to one step, the pulse bounces for ever and the check fails). The software GPU steps at only a few steps per second even with almost nothing awake, which is why it is not part of `test:gpu`. Run it after touching the electricity rules.
- **Simulation state** (what the grid holds, behavior over steps): the warm session below, with `readgrid.mjs`. Apart from `test:pulse` this is the only way to test sim behavior, since there is no test framework. A sim with nothing awake goes idle and stops stepping, so a loop waiting for `stepCount` to reach a target must also stop when `world.perf.idle` is true.
- **Does WebGPU work at all here:** `smoke.mjs` (under a second); if it fails the environment is the problem, not the sim.
- **A one-off look** at the DOM or the grid on a fresh page: `shot.mjs` / `readgrid.mjs` without `--session` (about 8 s each).

**Warm session (`session.mjs`).** Every fresh page pays about 7.5 s for the first GPU work (software shader compile, per GPU device). Measured: a persistent profile, a smaller window (14k cells instead of 54k) and a second page in the same browser all cost the same, so only keeping one page alive helps. `session.mjs start [url] [--width --height]` launches one Chromium, loads the app, compiles and leaves it running; later commands attach over CDP and take milliseconds (grid read 0.1 to 1 s, PNG 0.6 s, screenshot 0.13 s):
- `readgrid.mjs --session [--steps N] [--png out.png] [--resume]`, `shot.mjs --session [out.png] [--hide-canvas]`, `session.mjs eval "<js>"` (run anything on `window.__world`, e.g. `eval "__world.paintStroke(100, 30, 100, 30, {shape:'circle', radius:3, density:1, type:1})"`), `status`, `goto <url>` (pays the compile again), `stop` (kills the browser and a dev server it started).
- **Keep the sim stopped between commands.** `start` leaves it stopped, and reads stop it again. A running sim queues frames far faster than the software GPU finishes them and a readback waits for all of them: a read after 10 s of running took 55 s. To run it on purpose, `eval "__world.start()"`, then `--steps N` (run N steps, then stop and read) is the safe way to advance.
- The session state is in `$TMPDIR/idotdot-browser-session.json`; one session at a time (`--port` to change 9222).
- **The window must be big enough for the board**: the app shows the plain page and stops the sim when the canvas is under 600 px tall or the window under 320 px wide (about 760 x 650 and up for the full six-chip board). `start` opens the window 250 px taller than asked, so the app sees a big enough window on load, and trims it to the exact size afterwards; a requested size that is too small prints a note, and `settleSim` throws a plain-page error at once instead of waiting for a sim that will not start (it used to time out after 30 s).

What the sandbox does (each point cost time to find, so trust it before re-deriving it):
- **Flags** (`CHROMIUM_FLAGS`): the Vulkan/swiftshader set gives an adapter, `--use-angle=swiftshader` is what keeps the device alive (without it the GPU process dies on the first presented frame with "A valid external Instance reference no longer exists", which the app reports as a device loss), and `--disable-accelerated-2d-canvas --disable-gpu-rasterization` keep 2D canvas text off the GPU (the first `fillText` otherwise froze the page for about 9 s). The page must be on `http://localhost`: `navigator.gpu` does not exist on `about:blank`.
- **Speed:** after the compile the sim runs at a few steps per second on a full grid, far below the 60 the HUD's submit rate suggests. The header's `backdrop-filter` blur, composited in software over the canvas, cuts it further; `withPage` and the session switch it off (`FAST_COMPOSITING_CSS`).
- **`page.screenshot` shows the WebGPU canvas as blank white**, even while the sim steps. Screenshots are still right for the DOM; pass `--hide-canvas` to get the page background instead of white. To look at the world, use `readgrid.mjs --png`, which draws the grid with the registry colors (smoke, steam and water haze come out as plain tiles).
- **Reading state:** `window.__world` is the `GpuSimulation` (set in `main.ts`). `readGrid()` waits for every queued GPU command, hence the stop-before-read rule above.
- **Window size in a session:** a viewport override disappears when a connection closes, so `start` sets the real window bounds and corrects them by measuring the loaded page (the browser's own chrome changes the inner size).
- **Noise:** the dev server 404s `/favicon.ico` and Chromium logs it as a console error; `reportLog` ignores that one message unless a request made by the page also failed.

`plans/` holds design docs: `webgpu-compute-port.md` (how the GPU architecture came about) and `fire.md` (the fire/aging design; implemented, the tuning numbers in it are starting points). `board-in-world.md` is the design for anchoring the portfolio chips underground in each world (implemented; see its As built section). `bigger-chips.md` records the later change to 2x chips (two layouts more, pocket 3 dropped). Treat plans as intent; this file and the code are the current state.

## Architecture

### GPU simulation (`src/engine/gpu/gpu-simulation.ts`)
- `GpuSimulation.create(canvas, colliders, registry, cssW, cssH)` is async: it requests the adapter + device **before** `getContext('webgpu')`.
- **Grid = storage buffers.** One packed `u32` per tile: `type` bits 0–7, `value` 8–15, `variant` 16–23, `age` 24–31 (flat index `y*W+x`). Two buffers ping-pong (current = read, other = write). Zero-initialized = all air. Buffers rather than `r32uint` textures because WebGPU has `clearBuffer` but no texture clear/fill.
- **Step loop:** fixed 60 Hz timestep (rAF accumulator, max 5 steps/frame, backlog dropped). Per frame, **one** command buffer: brush stamps (if any) → for each step a compute pass of four **indirect** dispatches over the awake chunks (`clearChunk`, `main`, `mainLiquid`, `mainGas`; one 16×16 workgroup per chunk, one thread per cell) + the chunk pass (`CHUNKS_WGSL`) → swap; then the haze pass (only on frames that stepped) and the render pass. `onFrame(steps)` runs before encoding with the frame's step count (0 on high-refresh frames between steps), so per-step work like brush stamping stays refresh-rate independent. The per-step counter is a dynamic-offset uniform (`stepBuf`, one 256-byte slot per step) because all steps share a command buffer.
- **Conflict-free write model:** the awake chunks' write (and claim) cells are cleared to air by `clearChunk`; stayers write themselves, movers write their destination, air writes nothing. A mover's destination is air in the read state and claimed exclusively with an atomic (`atomicCompareExchangeWeak(...).exchanged`, first claim wins, loser stays — tiles are conserved). Tie-breaks are nondeterministic by design.
- **Chunk sleeping:** the grid is split into 16×16 chunks (`CHUNK_SIZE`). Every write that changes a cell goes through `commit()`, which marks the chunk (`marksBuf`); the chunk pass keeps a chunk awake for `SETTINGS.CHUNK_KEEPALIVE_STEPS` (at least 2) after a mark in its 3×3 neighborhood (`awakeBuf` countdown) and compacts the awake chunks into `activeListBuf` + the indirect args (`argsBuf`). Sleeping chunks are not dispatched and need no copy: a chunk only sleeps after a step with no change in it, so both grid buffers already match there. Movers may write into air in a sleeping chunk (the write marks it), but a fluid in a sleeping chunk cannot be displaced or stack-followed (`enterable` / `fallsAlong` check `chunkAwake`; trying wakes it). Random moves that have not fired yet must keep their chunk awake with `mark()` (friction rolls, liquid spread, reactions; gases always do), so a new stochastic behavior must too. Painting and wake-all (wind, collider changes) run the chunk pass before the first step so the touched chunks are awake.
- **Idle:** the awake chunk count is read back (`readActivity`); at 0 the sim stops stepping (`asleep`), the haze keeps blending for `SETTLE_STEPS`, then frames stop being submitted (`idle`; the canvas keeps its last frame and the rAF loop keeps running). `paintStroke`, `setWind`, collider changes and `resize` wake it; a readback from before a wake is ignored (`wakeGeneration`). `prefers-reduced-motion` freezes the wisp animation clock.
- `resize(cssW, cssH)` rebuilds all size-dependent resources (grid state resets). `rebuildSolidMask()` re-rasterizes colliders; `ColliderManager.onChange` marks it dirty and it is rebuilt at the start of the next frame. `readGrid()` is a debug readback (conservation checks). `snapshotWorld()` / `loadWorld(snapshot)` save and restore the grid (see World files). `stampCells(x, y, w, h, words)` overwrites a rectangle of cells with packed tiles (written to both grid buffers like `loadWorld`, then wakes everything; the board uses it for chip rings and to restore empty slots). `paintStroke(ax, ay, bx, by, brush)` queues a brush stamp swept along a segment (max `MAX_STAMPS` per frame); at the next stepping frame all stamps are uploaded and `PAINT_WGSL` rasterizes them on the GPU in one dispatch over their bounding box, before the sim steps.

### Shaders (`src/engine/gpu/shaders.ts`)
- `RENDER_WGSL`: full-screen triangle; maps each device pixel to a grid cell (`(pos - gridOrigin) / tilePx`, no stretching), air → background, else `colorTex[(type, variant)]`. Water haze is read per cell (blocky, matches the tiles); smoke and steam haze is sampled bilinearly between cell centers (`hazeSmooth`) so gas edges stay smooth on large tiles.
- `PAINT_WGSL`: rasterizes brush stamps (circle = Euclidean, square = Chebyshev distance to the stamp's segment ≤ radius; per-cell density roll and random variant from a per-stamp seed; the last covering stamp wins), skips solid cells, marks the painted chunks.
- `CHUNKS_WGSL`: per-chunk keep-alive countdown + awake list / indirect args (see Chunk sleeping).
- `STATS_WGSL`: counts non-air tiles and movers for the HUD. A mover always lands in a cell whose previous content differs, so movers = occupied cells whose type or variant changed (the value byte is ignored). Counting vacated cells instead undercounts: stacks shift together and displaced water/smoke swap into the mover's old cell.
- `COMPUTE_WGSL`: helpers `pack(t, value, variant, age)` (every write that keeps a tile passes its age along; a new tile from a reaction or aging passes 0), `passable` (in-bounds, air, not solid), `enterable(t, x, y)` (air, or a liquid/gas lighter than `t` in an awake chunk), `claim`, `commit` (write + mark), `mark`, `react`, `ageTile`, `rand` (hash of x, y, step), `updateFall`, `updateFlame`, `updateSpark`; entry points `clearChunk`, `main` (solids: reactions, then any type with non-zero gravity runs `updateFall`, other types stay put; `settle` writes a staying solid), `mainLiquid`, `mainGas`. Entry points pick their tiles by the per-type `phase`, not by type id.
- Uniform buffer (`UNIFORMS_WGSL`, shared by every module): 48-byte header (size, `tilePx` = tile edge in device px, wind, `gridOrigin` = device-px offset of grid cell (0, 0) in the canvas, `time` = wall-clock seconds, `frameSteps` = steps this frame, background; time and frameSteps are written every frame) + `types: array<TypeInfo, 256>` (gravity, phase, haze channel, reaction range `start | count << 16`, slide chance, density, rise speed, dissipation, cohesion, flags (`FLAG_CONSUMED`: some rule consumes the type; `FLAG_FLAMMABLE`: fire sticks to it; `FLAG_HOLDS_ON_FLAMMABLE`: a falling type holds still next to flammable tiles; `FLAG_FUEL_FED`: the type ages slower next to fuel; bits 8-15 = `blastResistance` * 255, `BLAST_RESIST_SHIFT`; `FLAG_EMITS_BELOW`: its emitter also fills cells below it), age rate, aged-out outcomes `start | count << 16`, emit type, emit chance + padding; 64 bytes each) + `reactions: array<Reaction, MAX_REACTIONS>` (other type, result, chance, consumes, radius + padding; 32 bytes each) + `outcomes: array<Outcome, MAX_OUTCOMES>` (result, chance + padding; 16 bytes each). All filled from the element registry in `writeUniforms`; unregistered types and air have haze `HAZE_NONE`.
- `updateFall` is parameter-driven and spends the tile's whole fall budget per step: it loops (max 8 attempts) over stride-down / slope-aware diagonal slide (both diagonals open → always roll; one open → roll with `slideChance`; none → rest; `slideChance` 1 = no friction) and claims only the final cell, falling back to shallower stride cells, the other diagonal, then earlier waypoints. Being blocked sheds the leftover fall fraction; otherwise it carries over.
- **Cohesion (wet sand, mud):** a type with `cohesion > 0` can hold still in `updateFall`. About to fall, it `clings` (with `cohesion` chance per step) to a cohesive tile beside it whose column is filled for `CLING_SCAN` cells (resting, not part of a falling stack); `fallChain` stops at a clinging tile, so the tiles above rest on it. About to roll off a slope, it stays (with `cohesion` chance) while touching a cohesive tile beside or below it, on top of the `slideChance` roll. Both are random holds, so they `mark()` and piles slump slowly to their final shape.
- Color on the GPU depends on `(type, variant)` only, never on `value`; types with an `ageRate` use `(type, age)` instead (`RENDER_WGSL` picks the color row from the age byte), so their `getColor(_, row)` is a 256-entry ramp over the tile's life.
- **Aging (generic):** a type with `ageRate > 0` gains `floor(rate)` age per step plus the fraction by chance (`ageTile`, mean lifetime about `256 / rate` steps) and `mark()`s its chunk every step, so the world only idles once every aging tile is gone. Past 255 the tile rolls once against its `agedInto` outcomes (chances add up to at most 1, in order; the rest of the time it vanishes) and turns into the one that hits, with age 0, through the same path as a reaction result (`settle` in `main`, `claim` + `commit` in `mainGas`; `mainLiquid` does not age). Painting and reactions write age 0, so new tiles start fresh; moves and stays must pass the tile's age through `pack`, or a moving tile would re-age from 0. The HUD mover count ignores the age byte.
- **Stack fall (all falling tiles + liquids):** a falling tile looks down through the falling tiles (in awake chunks) stacked under it (`fallChain(x, y, t)`, up to `SETTINGS.FALL_CHAIN`) to the open air below and shifts down with the whole stack, so stacks do not unzip into stride-sized gaps (bands). The destination can then be a cell the stack tile below is vacating, so a resting falling tile must claim its own cell (`claim` retries the weak compare-exchange's spurious failures); one that loses it (its stack did not fall) moves up into a vacated stack cell (`fleeUp`) so it is not lost.
- **Smoke (gas):** handled by `mainGas`, dispatched after `main` and `mainLiquid` in the same compute pass; `main` skips gases. Falling tiles and liquids are denser, so smoke is `enterable` for them and they claim its cell first; smoke may only write a cell it wins with `claim()` (its own cell included), so a displaced tile flees to a free neighbor or vanishes. `updateGas` (shared with steam) is advected by a flow field shared by all tiles (`SETTINGS.WIND` / `GpuSimulation.setWind(-1..1)` in the uniform header `wind : f32`, plus the curl of a smooth noise potential, which is divergence-free so it swirls without clumping or leaving voids) and buoyancy; tiles hold no velocity, speeds are move chances resolved with a shared per-step phase so whole patches move together (per-tile randomness or cohesion makes it look like water droplets); when blocked above it slides along the flow, and pockets (empty cells enclosed by `Smoke.POCKET_NEIGHBORS`+ smoke tiles) are closed by pulling in a less enclosed neighbor. `mainGas` (which also ages tiles and picks the mover: `updateFlame` / `updateSpark` for flames and sparks, `updateGas` for the rest) also dissipates it by chance (rise speed and dissipation come from the per-type table: `Element.riseSpeed` / `dissipationChance`). Smoke tiles are not drawn individually: `HAZE_WGSL` (on frames that stepped, separable tent blur of `Smoke.HAZE_RADIUS` tiles into a haze buffer that is blended over time by `Smoke.HAZE_TEMPORAL` per sim step, compounded over the frame's `frameSteps`) feeds `RENDER_WGSL`, which draws a translucent haze modulated by drifting noise wisps (`wisps`, driven by the header's wall-clock `time` so they animate smoothly at any refresh rate), colored from the `Smoke.getColor` light-to-dark ramp by density, over whatever is behind it. Tuning statics live on `Smoke` and are injected as WGSL consts.
- **Water (liquid):** same template, entry point `mainLiquid` dispatched after `main` and before `mainGas`; `main` skips liquids. Every liquid runs `updateLiquid(x, y, t)` with Water's tuning statics. Denser tiles sink through it (`enterable`: sand/dirt default density 1.5 > water 1 > gases), claiming first; displaced water flees up/sideways and is lost only if fully enclosed. `updateLiquid` falls (shifts down with its stack, see Stack fall above), slides diagonally, closes pockets (`pocketMove`, shared with smoke) and slides up to `Water.SPREAD_RANGE` cells per step toward the lowest surface along its row (`waterSlide`), else an occasional hop along a direction shared by row patches (`waterFlow`). Known: the incomplete top row of a pool keeps hopping (wander), so a pool's surface chunks never sleep and any pool on screen prevents idle. The haze pass is `vec4f` per cell (x smoke, y water, z steam, w methane); `RENDER_WGSL` draws water as a smooth body with a crisp `smoothstep` surface, colored by a global top-to-bottom gradient (`Water.SHALLOW_COLOR` to `Water.DEEP_COLOR` over the screen height). Tuning statics live on `Water`.
- **Steam (gas):** runs in `mainGas` through `updateGas` like smoke (faster `Steam.RISE_SPEED`). Its value byte is a condensation timer: it counts up while at least `Steam.CONDENSE_NEIGHBORS` neighbors are steam and drains by `Steam.COOL_RATE` otherwise; at `Steam.CONDENSE_STEPS` the tile turns into water with `Steam.CONDENSE_CHANCE` per step. Drawn as its own haze channel from the `Steam` color ramp.
- **Fire (flame, spark, ember):** the cycle is wood →(touching flame or ember, `Wood` rules) ember → (touching air, `Ember` rules; `with: AIR` works like any type) flame or rarely spark → flame ages into smoke; water puts flames, embers and sparks out, and water touching an ember turns into steam (`Water` rule; steam made inside a pool can be displaced and lost, which boils some water away). The ember turns into the flame rather than spawning one beside it, so no thread writes a second cell.
  - **Ember** is a cohesive, slow falling solid in `main` with an age ramp (bright orange to dark grey) that dies into air. It has `holdsOnFlammable`: while any of its 8 neighbors is flammable it does not fall (`clings`, so stacked tiles agree), so burning wood stays where it burns and the fire spreads along it instead of the embers dropping away. Embers also emit flames without being used up (the generic emitter, see Emitters). Air cells in awake chunks therefore scan their 8 neighbors for emitters each step.
  - **Flame** is a gas drawn as tiles (no haze channel, density 0.05) moved by `updateFlame`: it rises with chance `riseSpeed` and jitters sideways with `Flame.FLICKER` (more with wind, which also biases the direction), each rolled **per tile** with `rand` (smoke instead shares a step phase so patches move together). It tries `(dx, dy)`, `(0, dy)`, `(dx, 0)`, else keeps its cell, else vanishes (same claim contract as `updateGas`; no curl noise or pocket closing). A flame directly under a flammable tile holds still instead of rising or flickering, so it stays lit long enough to catch it. It ages from white-yellow through orange to red, then turns into smoke. It is `fuelFed`: next to fuel (a flammable tile or an ember) its age rate is multiplied by `Flame.FUEL_AGE_FACTOR`, so flames burn longer where they are fed.
  - **Spark** is a ballistic gas tile (density 0.3, so it flies through flames, smoke and steam) moved by `updateSpark`. Its velocity is in the value byte: `vx` bits 0–3, `vy` bits 4–7, each stored +8 (-7..7 cells/step), so value 0 means not launched and a fresh spark (reaction results and painting write 0) picks a random upward-cone velocity. Each step `Spark.GRAVITY` and `Spark.DRAG` change the velocity by chance; it traces the cells toward `(x + vx, y + vy)` (at most 7) through `enterable` and claims the furthest it can, falling back to earlier path cells. If the path was blocked it lands: `mainGas` writes a fresh flame in the cell it reached, which lights wood through Wood's flame rule. If the blocker is flammable (`Element.flammable`, e.g. wood) it sticks instead: it stays a spark in the cell it reached with value `SPARK_STUCK` (low nibble 15, a vx no launch produces) and Wood's spark rule keeps trying to light the tile until the spark fades; it lets go (falls) if no flammable tile is left around it. It fades through its age ramp and vanishes.
- **Charcoal / grass / stone / steel:** a burnt-out ember (`Ember.agedInto`: `CHARCOAL_CHANCE` charcoal, `ASH_CHANCE` ash, otherwise gone) sometimes leaves charcoal, a flammable falling powder that re-ignites into an ember (slower than wood). Grass is a high-friction flammable powder: mud touching it slowly turns into grass (`Mud.GRASS_GROW_CHANCE`, so a grass patch on mud keeps its chunks awake until the mud is used up), touching water it rots away, and flame/ember/spark/hot steel turn it into an ember at high chance. Stone is a plain static solid with high `blastResistance`. Steel is static, extremely blast resistant and conducts heat: fire turns it into hidden **hot steel** (aging, glows, `agedInto` cooling steel), which heats touching steel (`Steel.CONDUCT_CHANCE`), lights wood/grass/charcoal/bomb and dries wet sand/mud through those elements' own rules. Hidden **cooling steel** (aging, `agedInto` steel) is the refractory stage: it neither heats nor is heated, and must outlast hot steel (`CoolingSteel.AGE_RATE` < `HotSteel.AGE_RATE`), or heat would ping-pong through steel forever.
- **Electricity (live steel, arc, generator, shocked water, fuse):** rules plus data, no shader code; it copies the steel heat loop with a fast pulse. Steel touching live steel, a live fuse, shocked water (`Steel.PULSE_CHANCE`, about `60 * chance` cells/s along a one-cell wire), an arc (`ARC_CHANCE`) or a generator (`GENERATOR_CHANCE`) turns into hidden **live steel** (aging, 32 steps, flashes blue-white), which becomes hidden **spent steel** (aging, 64 steps, the refractory stage: it neither conducts nor is shocked, and must outlast live steel, or the pulse bounces) and then steel again; with `LiveSteel.OVERLOAD_CHANCE` per tile per pulse it ages into hot steel instead, so busy wires glow. Live steel and the **generator** (static, pickable, pulses steel forever, keeps its chunk awake like a torch) are emitters of hidden **arc** (static aging solid that dies into air, like the explosion); arcs start pulses in steel, shock water and ignite wood, grass, charcoal, bombs and methane, and live steel does the same at lower chances (a wire is a detonator). Water cannot age, so a pulse crosses a pool as hidden **shocked water** (static aging solid, 16 steps) then hidden **numb water** (refractory, 26 steps), then water again; shocked water plus numb water must outlast live steel. Only steel and water conduct: everything else insulates. **Fuse** (pickable) turns into hidden **live fuse** beside a pulse and burns out into air, leaving a gap; flames, embers and hot steel melt it. **Rubber** (pickable) is a flammable insulator that burns into a flame. Acid dissolves live and spent steel like steel. Design and tuning: `plans/electricity.md`.
- **Acid / ice / methane / mold:** all rules plus data, no per-element shader code except methane's haze channel. **Acid** is a dense liquid (1.2, sinks under water) drawn as tiles; consuming rules dissolve stone, steel (and hot/cooling steel), wood, charcoal, grass and mold at per-material chances, each dissolved tile using up the acid tile that ate it (it becomes smoke); touching water dilutes it into water. **Ice** is a static solid: Water's `FREEZE_CHANCE` rule freezes water touching it (a frost front), Steam's rule condenses steam into water on it, and flame/ember (radius 2), spark and hot steel melt it into water. **Methane** is a light gas (density 0.08, rises at 0.6) drawn as a haze in channel 3 (`Methane.HAZE_*`, `RENDER_WGSL` / `HAZE_WGSL`): flame, ember, spark or hot steel turn a tile into a flame (the flame rule is preceded by a rare `DETONATE_CHANCE` rule that turns it into an explosion, which restarts the blast at full reach), so a pocket flashes over and a big one explodes. It is released by mold exposed to air and by grass rotting in water (gas made inside water is usually displaced and lost, like steam). **Mold** is a static, aging, flammable tile (30 s life, `agedInto` dirt): Wood and Grass have rules turning them into mold when touching it, so a log decays wood -> mold -> dirt; acid and fire destroy it.
- **Emitters (ember, spring, torch):** `emit` (called for empty cells in `mainGas`) lets an empty cell pull in the product of a neighboring emitter (`Element.emitType`, rolled with its `emitChance` per emitter per step) without using the emitter up; the cell only writes itself, claimed like any mover. Cells beside or above an emitter qualify, cells below it only with `emitBelow` (`FLAG_EMITS_BELOW`). A static emitter `mark()`s its own chunk every step in `main`, so it keeps working after the area went quiet, and a spring or torch on screen prevents idle. **Ember** emits flames (`Ember.EMIT_CHANCE`), **Spring** (static) emits water in every direction and floods whatever it is in, **Torch** (static, not flammable) emits flames upward and sideways.
- **Ash / rubble / quench pairs:** ash (light loose powder) and rubble (heavy, high friction) come from aged-out outcomes: embers leave charcoal or ash, flames leave smoke (80%) or a spark (3%), fading explosion tiles leave smoke, flames, sparks and rubble. A quench pair is two one-sided rules that fire together on contact: hot steel + water (steel becomes cooling steel, water becomes steam), mud + acid (mud becomes dirt, acid becomes smoke). Each side rolls its own chance, so a pair is statistical, not simultaneous.
- **Explosion (bomb, explosion):** the blast is pulled in, never pushed, so no thread writes a second cell. `Explosion` (hidden) is a static solid with an age ramp that dies into air; its value byte is the reach spent so far (0 at an origin). Each step an empty cell (`blastFill`, in `mainGas`'s air branch before `emit`; solid-mask cells skipped, claims like any mover) or a non-air tile (`blastHit`, in all three dispatches right after `react`) next to a blast tile younger than `Explosion.SPREAD_MAX_AGE` turns into an explosion tile with age 0 and spent = the cheapest neighbor's spent + hop cost (`HOP_COST` orthogonal, `DIAGONAL_COST` diagonal, which keeps it round) + `blastResistance * ABSORB`, if that is at most `Explosion.REACH` (about `REACH / HOP_COST` cells). A tile holds with its `blastResistance` per step (and `mark()`s while the roll is pending), so tough materials stall and absorb the blast; none are immune. `Bomb` is a flammable static solid whose reactions turn it into an explosion on touching a flame, ember or spark, or any explosion tile (chance 1): reaction results start at age 0 and spent 0, so every bomb the blast reaches restarts the blast at full reach from its own cell and piles of bombs chain into one larger explosion. `react` runs before `blastHit`, so a bomb touching a blast always takes the reset path.


### Elements (`src/elements/`, `src/engine/element.ts`)
- **One class instance per element TYPE. Elements are display + tuning metadata only** (`type`, `name`, `displayName`, `defaultColor`, `getColor(value, variant)` (the second argument is the age for aging types), plus optional table fields: `phase` (`'solid'` default / `'liquid'` / `'gas'`), `gravityQuantum`, `slideChance`, `density` (default 1.5), `cohesion` (falling only, 0..1), `riseSpeed`, `dissipationChance`, `hazeChannel` (0 smoke-style, 1 water body, 2 steam-style, 3 methane-style; null = tiles), `flammable` (flames hold under it, sparks stick to it), `holdsOnFlammable` (falling types only: holds still next to flammable tiles), `fuelFed` (ages slower next to fuel), `blastResistance` (0..1, < 1 for every type: chance per step a tile holds against an adjacent explosion), `hidden` (not listed in the picker), `ageRate` (age steps per sim step, 0 = no aging), `agedInto` (list of `{ type, chance }` outcomes after age 255, default none = vanishes), `emitType` / `emitChance` / `emitBelow` (emitter, see Emitters), `reactions`). Per-tile behavior is WGSL in the compute shader, driven by these per-type tables.
- **Reactions** (`Reaction { with, becomes, chance }`, at most `MAX_REACTIONS` (128) in total, validated by the registry): one-sided; a tile touching (8 neighbors) a `with` tile turns into `becomes` with `chance` per step, and only the owning tile changes (conflict-free). Give the other element its own rule for a two-sided reaction. A non-consuming rule can set `radius` (Chebyshev distance, default 1 = the 8 neighbors, at most `MAX_REACTION_RADIUS` = 8 so a change in range always wakes the reacting chunk; `typeWithin`). With `consumes: true` the touched tile turns into air in the same step, exactly one per conversion (`reactConsuming`: each tile offers its rule to one touching `with` tile per step, picked by a per-step hash; the touched tile takes the first offer in neighbor scan order; both sides recompute the same offer from the read state, so no atomics are needed; both chunks must be awake; an offer that is pending, i.e. a `with` tile is touching, `mark()`s the offering chunk so it stays awake). Types some rule consumes have `FLAG_CONSUMED` set (only they scan for offers); the registry rejects two elements with consuming rules where one consumes the other. A reaction result of `AIR` makes the tile vanish (no write); a rule can also have `with: AIR` (the tile reacts where it touches air). Applied in all three dispatches; a touching rule that has not fired keeps the chunk awake. Sand → wet sand and dirt → mud consume the water they touch; both also soak without consuming within `SOAK_RADIUS` of water (`Sand` / `Dirt` statics), so sand or dirt dropped into a pool ends up mostly wet sand or mud. Heat reverses it: wet sand and mud turn back into sand and dirt within `HEAT_RADIUS` (2) of a flame or ember and when touching a spark (`WetSand` / `Mud` statics).
- Register every element in `src/elements/index.ts` (`createElementRegistry`); the header picker lists all registered elements automatically (except `hidden` ones), and the color texture is built from `getColor(0, variant)` for variants 0–255.
- Falling elements need no shader work: set `gravityQuantum` (and optionally `slideChance`, `density`) on the class. A new liquid or gas needs none either: set `phase` (+ `density`, `riseSpeed` / `dissipationChance` for gases, `hazeChannel` to draw it as haze); it then shares Water's flow tuning or the smoke flow field. Other moving behavior needs a new WGSL function dispatched from `main` (write through `commit`, and `mark()` any random move that has not fired). Static elements need none.
- `gravity.ts`: `computeGravityQuantum(base, scale, offset)` → fixed-point quanta (256 = 1 cell/step). The fractional remainder accumulates in the tile's **value byte** (shader owns it for falling elements).
- `colors.ts`: `buildVariantColors(base, count, variance)` precomputes deterministic per-variant channel shifts; `buildGradient(stops, count)` samples a piecewise-linear ramp (the per-age colors of aging elements).

### UI (`src/main.ts`, `src/ui/`)
- 48px header (`ui/header.ts`), overlay layer (`ui/overlay.ts`) converts DOM rects to grid colliders; element picker (`ui/picker.ts`); brush picker (`ui/brush-picker.ts`). Both pickers mount into `#header .header-actions`.
- Canvas has `pointer-events: none`; painting listens on `window` and skips header/overlay targets. Brush: circle or square, density-gated, calls `GpuSimulation.paintStroke` (rasterized on the GPU, collider cells skipped); Air is the eraser. Painting is unconditional overwrite (no occupancy check). It stamps once per sim step (not per frame), sweeping the brush along the pointer's path since the last stamp, so fast drags leave a continuous stroke; a press is stamped on the next step even if released before it.
- **Pixel-perfect layout** (`engine/grid-geometry.ts`, `ui/frame.ts`): everything is laid out in whole device pixels so no zoom or pixel ratio (browser zoom 110%, a 2.625x phone) leaves the canvas stretched or the DOM off the tile grid. `computeGridGeometry` (pure, shared by `GpuSimulation.resize`, the test harness and the Node geometry test) gives the canvas the largest whole number of device pixels that fits and sets its CSS size to exactly backing / dpr; the 48 px header is snapped to whole device pixels (`headerHeight()`, published as `--header-height`, which the header, `#overlay` and `#sandbox` use), so the canvas starts on a pixel edge. Call `applyHeaderHeight()` on load and every resize, and use `headerHeight()` (not `SETTINGS.HEADER_HEIGHT`) wherever the canvas offset matters.
- **Tile size**: `SETTINGS.TILE_SIZE` CSS px (4; changed at runtime by the perf HUD's Tile Size dropdown via `GpuSimulation.setTileSize`, which rebuilds the world like a resize, so the grid clears), snapped to a whole number of device px (`tilePx = round(TILE_SIZE * dpr)`, so `GpuSimulation.tileSize` = `tilePx / dpr` can be fractional), grown if an axis would exceed `MAX_SIM_DIMENSION` (2048) cells. The grid is `ceil(canvas / tilePx)` cells, anchored to the canvas bottom (the floor row sits on the edge; the top row may be partly hidden; `originY` <= 0 is grid row 0's CSS y). Map CSS px to cells with `GpuSimulation.cellAt` (pointer) or `tileSize` + `originY` (`Overlay.measure`). Sim tuning is in tiles per step, so on-screen speeds scale with the tile size.
- **Resize rebuilds the world**: grid state resets; colliders persist (they belong to overlay content). `Overlay.registerCollider(el)` keeps the element and re-measures it when it resizes (`ResizeObserver`) and after each window resize (`refreshColliders`); `unregisterCollider` removes it. The solid mask rebuilds automatically. Window resizes are coalesced to one rebuild per animation frame.
- Perf HUD (`ui/perf-hud.ts`): third header button toggles a small readout under the header (fps/ms, tiles, moving vs resting, awake chunks + idle, GPU ms, steps/s, grid) and a Tile Size dropdown (1/2/4/8/16 px; the panel's clicks don't paint). The text is color-coded for low fps and for dropped sim steps (`perf.droppedStepsPerSecond`: backlog beyond `MAX_STEPS_PER_FRAME` discarded while the sim is awake, i.e. it ran slower than real time). `GpuSimulation.perf` holds the numbers; the tile counters (`STATS_WGSL`) only run while the HUD is visible. "moving" = tiles that changed cell last step (see `STATS_WGSL`).
- **Preferences** (`ui/preferences.ts`): tile size and the brush shape / radius / density are saved to `localStorage` (key `idotdot.preferences`) when changed and restored at startup (`loadPreferences` validates every field and falls back to defaults; blocked storage is ignored). `main.ts` passes the saved tile size to `GpuSimulation.create` and to `PerfHud`. The selected element is not saved. A saved tile size other than 4 px means default worlds load resampled.
- A lost device (`GpuSimulation.onDeviceLost`) shows the blocking popup in `ui/gpu-error-dialog.ts` (plain statement, a Reload button and a link to the plain view). A missing `navigator.gpu` or a failed device creation shows the plain page with the fact stated at the top instead.

### World files (`src/engine/world-file.ts`, `src/worlds/`, `src/ui/world-menu.ts`)
- `.idw` = 16-byte header (magic `IDW1`, width u16, height u16, tile size in CSS px f32, 4 reserved) + gzipped packed grid words (`CompressionStream`). Type ids are stable constants: never renumber them or saved worlds corrupt. `encodeWorld` / `decodeWorld` validate; `resampleWorld` / `fitWorld` are pure (no GPU), so they can be checked in Node.
- `GpuSimulation.loadWorld` resamples the world by saved/current tile size (enlarging repeats cells; shrinking takes the most common non-air type of each block, air when most of it is air), anchors it bottom-center (crop/pad), clears collider cells and unregistered types, writes both grid buffers and wakes all chunks. `resize` / `setTileSize` still clear the grid; `main.ts` then calls `loadDefaultWorld` (after `refreshColliders`, so the solid mask is current).
- Default worlds are `src/worlds/*.idw`, bundled by `import.meta.glob`. `pickDefaultWorld()` (`src/worlds/index.ts`) chooses once per visit (random, or `?world=<file base name>`) and caches it, so resizes reload the same world; no files or a decode failure = start empty. Author one with the header Save / Load buttons (`WorldMenu`): paint, Save, move the file into `src/worlds/`. Author at 4 px tiles; other sizes are lossy resamples.
- **The shipped worlds are generated, not hand-painted**: `tools/make-worlds.ts` runs the scene scripts in `tools/worlds/` (`alchemist-lab`, `farmstead`, `death-machine`) on the drawing kit `tools/world-kit.ts` (`Grid`: primitives, brick patterns, ASCII `stamp`, `pipe`, `vessel`; deterministic seeded RNG, so a regenerated file is byte-identical) and writes `src/worlds/*.idw`. Edit the script and rerun `npm run worlds`; do not hand-edit the `.idw` files. Each is 640x348 tiles (1440p at 4 px), anchored bottom-center like every world, so the story sits in the middle 480 columns and the bottom 258 rows that a 1080p screen shows. Each places 25+ of the 27 element types.
- **The board block in every world** (`tools/worlds/underground.ts`, geometry from `src/worlds/board-slots.ts`): the five shared pockets are pocket 1 (left), pocket 2 (narrow, 52 wide, left of the hall), pocket 4 (52 wide, right of the hall at column 436), pocket 5 (moved to column 494) and pocket 6; there is no pocket 3, because the block and its gallery fill the bottom 150 rows of a 600 px canvas and leave nothing under them. `POCKETS` is a list of five, so room draw lists have five entries (`carvePockets` takes per-world `tweaks`). `boardHall` carves a brick-lined air hall around the block so every ring material shows against a dark recess, `galleryCorridor` the lined corridor whose air interior carries the DOM controls, `pipeLattice` one pipe along the 4-row strip between the chip rows (`ROW_STRIP`, clear of every ring in all three layouts; there are no vertical pipes between the columns, because the narrow chips sit across that gap), and `lined` stone-lines any other cavity (a methane duct, a drain) so loose rock lenses cannot slump in. `finishBoard` runs last: it turns mud lenses near the block into dirt, then fails the build if the zone around a slot (ring plus `KEEP_OUT_CELLS`) holds anything that acts on its own (water, acid, gases, fire, torch, spring, explosives, hot steel, mold, mud), a gallery cell is not air, or the hall or gallery leaks into other air. Conduits cannot cross the block: they run through the rock above it (rows 170 to 197) or down its east side (the farm's drain, the lab's greenhouse drain and the death machine's methane spine all end in pocket 4). Do not `lined` a duct before a `shaft` that must open into it: `shaft` walls ignore its end row, so carve ducts below the soil walls (rows 156 to 174) or re-carve the bore afterwards.
- **Authoring rules learned from running them** (the sim is the only judge; a software WebGPU in headless Chromium runs about 2 steps/s at full size): acid eats stone, steel, wood and mud within seconds, so hold it in ice (glass) vessels; a spring emits about 7 water/s forever, so give it a sink (or accept a flood after minutes); torches throw ballistic sparks that light flammables up to ~60 cells away, so keep wood, grass and charcoal away from torches unless the fire is the point; steam made inside water is lost, so only water touching hot steel at its surface makes steam; heat runs along a steel bar at about 2 / 4.5 / 5.5 / 6 cells per second for widths 1 / 3 / 5 / 7, which sets the length of a fuse; static solids never fall, powders (sand, ash, grass, charcoal, rubble) must rest on something and hold slopes of 45 degrees or less; keep bombs 3+ cells from steel the heat can reach.
- `tools/make-rooms.ts <world> <room> --out <dir>` renders one room of a scene script alone in a small grid, so it can be simulated quickly (rooms are the `ROOMS` exports of the scene scripts).

### Colliders (`src/engine/collider.ts`)
- Rect list in grid coordinates, rasterized into the GPU solid mask (`forEachRect`). Solid cells are not passable.

## Conventions

- **Portfolio copy and UI** (anything visible that the portfolio adds): no em-dashes (use commas, colons or full stops); no punchline one-liners, runs of short sentences, "X is the Y of Z" definitions or "not just X but Y"; error and empty-state copy states the fact plainly (no "Oh no!", no emoticons). Monospace is for real readouts like the perf HUD only. No numbered step sections or bullet lists by default, no stock cards (dark panel, 1px light border, soft shadow, rounded corners), no blinking-dot or status badges, and not one bordered rounded translucent button on every control. Keep the simulation as the page: no hero, feature-grid or badge layouts. A new visible element gets its own shape or treatment and does not copy `.picker-button` or the dropdown recipe; panel edges come from tiles, not CSS borders, radius or shadows.

- **Strict TS**: `noUnusedLocals`/`noUnusedParameters` — prefix intentional unused params with `_`. JSDoc block comments on classes and exported functions explain *why*, matching existing files.
- Global tunables live in `src/settings.ts`; per-element tuning lives as `static` fields on the element class (e.g. `GRAVITY_SCALE`, `SLIDE_CHANCE`, `*_VARIANT_COUNT`, `*_COLOR_VARIANCE`, `AGE_RATE`).
- Adding an element: run `new-element.bat <name> <falling|static|bare>`, pick a color and tweak the statics, then add its WGSL behavior if it moves.
- Add 1-3 line comments for any global or public API-like methods. Otherwise avoid code commenting unless the code is unconventional or rule-breaking. Code itself should be clean and readable so it is understood without comments.
- WGSL gotchas: mixing `*` and `^` needs parentheses; unused bindings are dropped from `layout: 'auto'` (the compute pipeline uses an explicit layout); uniform arrays need 16-byte element stride (`TypeInfo` is 64 bytes, `Reaction` 32, `Outcome` 16). The compute layout uses 7 of the default 8 storage buffers per stage.

## Gotchas

- Air must remain type 0; the registry rejects a non-zero type named `air`.
- `SETTINGS.GRAVITY: 0` disables gravity for all falling elements.
- WebGPU lacks `fillBuffer`/`fillTexture`; `getPreferredCanvasFormat` is on `navigator.gpu`. `src/engine/gpu/webgpu.d.ts` declares only what the bundled DOM lib is missing — verify any new declaration against a real browser.
- A canvas locks to its first context type; GPU init acquires the device before `getContext('webgpu')`.
- Never write `writeBuf` directly in the compute shader: use `commit()` (or `markCell` for a tile that vanishes), or the changed chunk may fall asleep with its two grid buffers out of sync (tiles reappear or vanish on the next swap).
